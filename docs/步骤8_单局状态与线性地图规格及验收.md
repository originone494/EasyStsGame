# 步骤8：单局状态与线性地图

日期：2026-10-30（Australia/Perth）。基线`8d861b3`，开发分支`dev/v15.7-step8-run-map`，备份`backup/v15.7-before-step8-20261030`。依据实施方案步骤8及完整策划案第2节；上传原文保持不变。

## 开发前执行规格

单局独立管理角色、共享生命／上限、永久牌组、遗物、金币、三项适应、地图、当前楼层／节点、已完成节点、付费删牌／升级次数、待确认战斗结果与单局状态。战斗只负责当前节点的战斗临时状态；跨战斗不携带手牌、消耗区、天气进度、临时监听或次数计数。

先生成每层固定战斗骨架：第1层9场非Boss＋1Boss、第2层6＋1、第3层4＋1，共22场；精英替换非Boss名额。用户最新确认：每层随机插入5个非战斗节点，至少1个商店、1个火堆；另加一个固定紧邻Boss的火堆，不计入这5个。故每层6个非战斗节点，全局40节点。此条覆盖原文“Boss前火堆计入火堆总数”的计数方式，原文保留不改。任何随机节点均不得插入固定火堆与Boss之间。同种子配置可复现完整地图和每节点战斗种子，查看地图不消耗战斗或地图随机数。

当前节点依次完成；未来和已完成节点只允许查看，不能进入或重打。普通战或Boss失败结束本局；第一、二层Boss成功确认结果后进入下一层；第三层Boss成功直接通关，无奖励或第四层。进入下一节点必须使用本局当前资产，不能从独立测试战斗带入调试卡。

实际卡牌／遗物奖励池与招募属步骤9，商店、火堆服务和具体事件属步骤10。本步接通节点进出，不凭空发放未实现的物品、治疗或强化。金币与属性仍在战斗结束时按现有规则只发一次；未来选卡／遗物资格保留在战斗结果记录中，本步不伪造实际领取。

额外3个随机非战斗名额的类型先采用可调等权配置，不将其冒充正式权重。精英数量／基准已向用户询问，配置与生成算法分离。

## 实现与操作

- `game/map.ts`先建立战斗骨架和连续1～22战编号，再把5个随机安全节点插入非Boss战之后的间隙。各间隙内随机排序，最后再追加固定火堆与Boss，保证任何随机节点都不插入两者之间。节点有稳定ID、独立战斗种子与奖励快照；`content/map.ts`集中管理配置。
- `game/run.ts`提供开局、进入当前节点、战斗操作与同步、确认结果、离开安全节点。每次转换返回新状态；`runId`区分同种子的新局，节点的种子与内容仍由地图种子复现。战斗在开始效果前即关联当前单局／节点，外来上下文不能提交到当前流程。
- 角色、共享生命／上限、永久牌组升级标记、金币、三项适应与遗物定义跨战斗保留；已持有遗物不因本场停用而永久丢失，新战斗重置启用／次数。手牌、抽弃／消耗／执行区、天气进度、伤害修正和临时监听重新初始化。计费次数保留，商店收费操作尚未接入。
- 战斗终止时按现有规则只发一次金币／适应，单局同步已发资产；确认结果只记账并推进，不再发奖。卡牌／遗物资格保存在`pendingReward`及确认后的`rewardHistory`中，本步不生成物品或暗中加入队伍。最终Boss无待发奖励。
- 精英默认不生成，因为数量和基准未获答复。生成器支持按配置替换非Boss名额并展示精英与其奖励；算法测试中的精英数值仅为测试输入，不作为正常内容启用。正式怪物／Boss数值与难度平衡仍属步骤12，地图复用现有测试布局。
- “开始冒险”会建立全新正常七张牌组，不携带独立测试局面的资产或调试牌。也可通过`?mode=run&seed=157`进入地图。三个楼层可提前查看，未来／已完成节点只显示详情，没有进入或重打入口。
- 单局战斗的“查看地图”可临时查看未来楼层，再返回原战斗；不执行回合、发奖或消费随机数。单局不开放本场重开、切换测试布局或旧三布局继续入口，失败只能重新开局。
- 第一、二层Boss成功确认结果后进入下一层，属性上限读取50／100／200且不重置旧属性；第三层成功直接通关、无第四层。重新开局清空进度和资产，返回试战则退出本局。刷新仍重开；JSON状态可序列化，但浏览器自动存档及版本迁移留待步骤13。

## 安全节点与开发入口

商店、火堆、事件各有进入后的独立页面，可查看地图后返回当前节点，再继续前进。当前没有商品／收费、恢复生命、升级或事件奖励，不借安全节点发放额外资源。具体服务按步骤10实现。事件在地图只显示“？”，进入后才展示当前空遭遇。

`?mode=run&scenario=runRoute&seed=157&debug=events`是完整路线开发局面：与正常地图完全相同，但永久牌组仅有“路线验证（测试）”，对全部敌人造成100基础伤害，便于快速逐场操作22战；Boss仍须实际接触才结算。该卡只在此固定局面出现，正常“开始冒险”与重新开局都恢复七张普通牌组，不是正式平衡或正常通关路线的证明。`debug=events`可查看单局记录、当前节点、资产、战斗及结果记录。
