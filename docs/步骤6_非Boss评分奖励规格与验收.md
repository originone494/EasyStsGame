# 步骤6：非Boss评分与奖励

日期：2026-10-30（Australia/Perth）。基线 `5a612d6`，开发分支 `dev/v15.7-step6-rewards`，备份分支 `backup/v15.7-before-step6-20261030`。

## 开发前执行规格

按本场所有普通怪物的最大生命总量加权：评分比例 = 有效生命损失总和 ÷ 最大生命总和，限制在0～1。每只怪物分别保留原始计分最大生命、累计有效生命损失及移除原因；死亡或接触消失不删除其计分记录。只计实际扣血，单只累计最多计其原始计分最大生命；过量伤害、接触移除和0伤害不额外加分。卡牌、遗物、明确间接伤害导致的实际怪物扣血同样计入。

普通战成功完成后，金币和每项适应分别按 `ceil(基准 × (0.2 + 0.8 × 评分比例))` 计算，只在最终取整；属性再受所在楼层上限约束，溢出直接作废。失败没有保底奖励。卡牌奖励资格不参与评分缩放；实际三选一流程留给步骤9，不提前制作角色卡池。

最后击杀的卡牌直接效果和触发链完成后才结算奖励；最后怪物接触消失且队伍存活时按原规则立即结束并正常结算。结算与战斗触发队列分离，不因发奖再次触发死亡或击杀监听，重复渲染、重复结束调用不能重复发奖。Boss接触入口不使用非Boss保底公式，Boss挑战与奖励另在步骤7实现。

用户已确认使用可调测试值：三层每项适应上限50／100／200，普通战满评分基准20金币＋5点该场指定适应。统一配置在 `src/content/economy.ts`，不是最终平衡数值；精英基准和楼层增长曲线未定。现有三个普通布局分别奖励晴、雨、风适应，当前都按第一层上限50处理；实际楼层由步骤8地图接入。当前天气与战斗指定奖励属性独立。

治疗、复活、召唤和最大生命变化的完整计分归属仍待后续内容规则；当前普通怪物没有这些正式能力。现有防御性账本冻结初始计分最大生命并限制单只累计计分，不能据此认定未来召唤物或复活单位的正式规则。

## 实现与可操作行为

- `game/scoring.ts`维护逐怪物计分账本，伤害批次在写入生命前验证计分，生命与计分整体提交；接触移除只改移除原因。
- `game/rewards.ts`使用整数分数计算奖励：`ceil(base × (maxHp + 4 × hpLost) / (5 × maxHp))`，避免浮点误差或展示百分比的四舍五入造成多发。每项先独立向上取整，再限制新增量，溢出不折算金币。正常属性不会突破上限；调试预设已经超限时保留旧值且不再增加。
- 战斗终止时一次提交金币、属性和领取记录；失败及Boss接触入口不套用普通胜利保底。界面渲染不发奖，JSON恢复保留已领取标记。
- HUD显示当前评分、有效扣血与金币；结果页显示评分、实际奖励比例、金币、指定属性和溢出。卡牌三选一资格写入结果数据，不展示尚未实现的选卡界面。
- 正常胜利可“继续战斗”，暂按三个测试布局循环，保留当前生命／最大生命、金币、适应、永久牌组与遗物；恢复本场消耗牌，重置战斗次数，清除临时监听。固定开发局面不开放继续，防止调试卡混入普通牌组。
- “重新开始／再战一次”恢复当前战斗开局快照，包括开局金币、属性、生命、天气与牌序，不叠加本场奖励；“切换测试战斗”仍创建独立默认开局。刷新仍重开，不是存档功能。

## 开发局面与预期

地址增加 `?scenario=...`，再加 `&debug=events`可查看评分账本、金币和奖励数据。

| scenario | 操作 | 结果 |
| --- | --- | --- |
| scoreZero | 结束回合 | 0%评分胜利，20%奖励，即4金币＋1晴适应 |
| scoreHalf | 击杀1号，再结束回合 | 50%评分，60%奖励，即12金币＋3晴适应 |
| scoreSeventyFive | 击杀1号，削弱2号，再结束回合 | 15／20有效扣血，75%评分，80%奖励，即16金币＋4晴适应 |
| scoreFull | 击杀1号 | 100%评分，20金币＋5晴适应 |
| scoreCap | 击杀1号 | 开局晴适应49，实际＋1至50，4点溢出；金币仍＋20 |
| scoreDefeat | 结束回合 | 接触致死，0奖励，无继续入口 |

上述局面固定初始雨天，避免晴适应预设改变测试卡伤害。正式七张初始牌组不含测试卡。
