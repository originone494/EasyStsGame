## 执行规格

1. 合法出牌后先进入独立执行区。按描述完成直接效果，期间只更新状态并记录事件，不立即触发监听。非法操作不记录出牌事件、不消耗卡牌。
2. 延续原型离手时点：直接效果完成后进入弃牌／消耗区，再处理队列。卡牌自身直接抽牌时仍在执行区，不会抽回自己；监听触发抽牌时普通已使用牌可参与后续洗牌。死亡中断时仍完成牌区归位，不执行或记录后续卡牌效果。
3. 事件先进先出。当前事件的所有响应完成后才处理下一事件；响应产生的新事件追加队尾。处理器禁止递归派发；不设置全局连锁次数截断。
4. 一只怪物完成正常移动或接触后，若战斗继续，处理其事件队列后再轮到下一只。整轮行动顺序仍按回合开始时距离／编号锁定。
5. 第一回合和后续回合均记录TURN_STARTED。回合开始监听先执行，再补手牌至配置数量，再处理抽牌事件。未来天气更新应放在TURN_STARTED之前。
6. 玩家生命归零立即失败，取消剩余直接动作、当前响应余下动作、同事件其他响应和所有排队事件。已发生的事实不回滚。
7. 非Boss最后怪物被击杀进入closing：继续当前卡牌其余合法动作及触发链；没有合法目标的动作跳过，独立治疗／抽牌继续；队列和执行区清空且玩家存活才胜利。触发造成最后击杀同样适用；收尾内玩家死亡仍立即失败。
8. 非Boss最后怪物接触消失，玩家存活则立即胜利，取消队列，不再响应接触或生命损失监听；接触致死优先判失败，接触移除不产生ENEMY_DIED。
9. 统一终止入口支持boss-contact原因，不扣队伍生命也可立即终止并取消队列。当前没有Boss实体或累计伤害判定，正式Boss接触调用留给步骤7；相关测试验证的是终止入口，不是完整Boss玩法。

## 事件与状态

`game/model.ts` 的 `GameEvent` 含id、sequence、type、source、actor、target、value、parentId、allowChain。实体引用区分player／enemy／card／relic／temporary／system，避免不同对象编号冲突。碰撞另记录实际撞击者actor，卡牌或遗物作为来源source。

| 事件 | 记录条件 |
| --- | --- |
| CARD_PLAYED | 卡牌合法打出 |
| DAMAGE_RESOLVED | 实际完成一次伤害结算，包括0伤害 |
| HP_LOST | 实际扣除生命；值封顶实际减少量，过量伤害不放大 |
| ENEMY_DIED | 普通敌人真正生命归零；父事件为致死伤害 |
| ENEMY_CONTACT | 普通怪物真正尝试进入队伍格 |
| COLLISION | 实际怪物间击退碰撞；无自动碰撞伤害 |
| UNIT_MOVED | 实际位置改变，value为有符号位移 |
| CARD_DRAWN | 一张卡真正进入手牌 |
| CARD_EXHAUSTED | 卡牌完成直接效果并进入消耗区 |
| TURN_STARTED | 玩家第一回合及后续回合开始 |
| HEALED | 完成治疗结算，值为实际恢复量，可为0 |

卡牌直接效果以CARD_PLAYED为父事件；伤害导致的HP_LOST及ENEMY_DIED以伤害为父事件；监听产生事件以当前出队事件为父事件。系统和普通怪物的独立事件可无父事件。原 `events` 六种事实记录继续供浮字和既有测试使用，不承担调度。

状态区分player、card、events、enemy、closing、finished。`eventQueue`为未处理队列，`eventHistory`保留所有已发生事实，`eventTrace`记录入队／出队／快照／执行／跳过／取消／结束。均为可结构化克隆及JSON序列化的数据，不保存函数。

## 监听与快照

`registerListener`按生效时间分配统一登记序号，卡牌临时监听与遗物混排。遗物按获取顺序登记，停用／恢复保留其获得顺序；临时监听恢复时重新登记。支持整个战斗有效、回合结束到期、手动停用／恢复、每回合限次、每场限次及不限次数。计数只在实际触发时增加。

一个事件出队时，先统一冻结全部遗物的资格及非目标数值，然后依登记序号执行；前序治疗或停用不改变同事件已锁定的后序资格和值。下一事件重新判断。响应中注册的新监听不插入当前快照，从后续出队事件起参与判断。

自动目标按每个依赖目标的动作实际执行时选择；支持事件原目标、最近、最低生命及固定种子随机目标。无目标时不生成虚假0伤害事件，也不消费选目标随机数。目标相关生命值在选定后读取；混合公式分别使用锁定的非目标部分及当时的目标部分，再最终向上取整。

数值配置支持常量、已损生命、事件数值、目标生命与倍率，效果支持治疗、抽牌、直接失去生命、单体伤害／击退、监听登记和启停。卡牌直接效果也可登记监听。新增配置无需在事件调度器增加按遗物名称判断的分支。

临时卡牌监听的统一快照规则尚未正式定案，因此框架要求其显式指定eventStart（出队时冻结）或execution（自身执行时判断／读取非目标数值），缺失策略会报错，不自动将遗物规则推广为正式卡牌规则。

`allowChain=false`表示该监听产生的事实仍记录并出队，但不能继续触发监听；true允许后续触发。测试验证了按具体次数配置完成160次自动响应，没有隐藏全局次数上限。正式内容仍应避免无法交还操作的无终点自动闭环。

## 开发局面

以下URL均可通过 `npm run dev` 后的游戏地址进入。正常入口保持原有三个战斗和七张牌，不装配测试遗物。开发局面重开会恢复预设状态；测试遗物及新增开发卡均不作为正式内容。

| URL参数 | 操作与预期 |
| --- | --- |
| `?scenario=events&debug=events` | 打出收尾治疗击杀唯一敌人：直接治疗5、死亡遗物治疗3、回响治疗1；最终16/20生命胜利 |
| `?scenario=snapshots&debug=events` | 对唯一敌人打出零伤害：先治疗5，再按锁定的15点已损生命造成伤害；队伍10/20，敌人15/30 |
| `?scenario=eventLethal&debug=events` | 使用生命代价：3点生命付出3点立即失败，后续卡牌治疗及遗物治疗均取消 |
| `?scenario=eventTarget&debug=events` | 使用零伤害：前序遗物杀死目标，后序攻击跳过但治疗2继续；最终9/20生命胜利 |

添加 `debug=events` 才显示可展开、滚动的开发事件查看器，展示事实、父子关系、队列、监听计数及调度日志，结算后仍可查看。普通界面不显示实现信息。既有heal／empty／lethal／chain入口保持可用。
