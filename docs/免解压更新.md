# Windows：下载一次，以后双击更新

## 使用前提

此方案从 `https://github.com/originone494/EasyStsGame` 的 `main` 分支更新游戏。启动器仅下载已推送到该分支的版本，不会获取尚未推送的云端修改。

## 首次使用

1. 安装 Node.js 24 LTS 和 Git for Windows（各安装一次，默认选项即可）。已安装者跳过。
2. [下载单独的启动游戏.cmd](https://github.com/originone494/EasyStsGame/raw/refs/heads/main/启动游戏.cmd)，保存在桌面或其他固定位置，无需 ZIP、无需解压。
3. 双击。首次自动下载游戏、安装依赖，然后打开浏览器。

之后每次双击同一个文件，会检查新版，更新后启动。关闭终端窗口即可停止服务。游戏安装在 `%LOCALAPPDATA%\EasyStsGame\repository`，不要求放在桌面，不需要管理员权限。

私人仓库需要当前电脑具备 GitHub 仓库访问权限；通过 Git for Windows 的正常登录完成，启动器不包含也不要求粘贴令牌。

## 更新与文件保护

- 更新仅快进合并（`git pull --ff-only`），不 reset、不删除存档、不强制覆盖文件。
- 有本地修改或其他分支时跳过更新，启动现有版本。
- 网络暂不可用时，尝试启动已安装版本；首次安装或新依赖仍可能需要网络。
- 仅首次安装、锁文件／Node 版本变化、或依赖缺失时运行 `npm ci`。
- 来源不符、Git 状态不可确认或依赖安装失败时停止，并保留文件。
- 游戏仅监听本机地址，浏览器自动打开。当前第一阶段仍未实现游戏内存档。

## 维护与验证

`启动游戏.cmd` 是生成的单文件，包含启动逻辑，不需要额外下载脚本。维护源为 `scripts/windows-launcher.cjs`。修改后执行 `node scripts/build-launcher.mjs` 重新生成。

`node tests/launcher/launcher.test.cjs`：9 项逻辑测试，覆盖初装、更新、锁文件标记、本地改动、不同来源、网络失败及安装失败。已在 Linux Node.js 24 通过；没有 Windows 图形机器，尚未进行 Windows 双击实机验证。游戏本身已在 Chromium 验收。

启动器的更新能力依赖维护者后续把新版提交到仓库。它不能自动获取尚未推送的云端文件。
