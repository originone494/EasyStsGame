# 步骤4：同步击退执行规格与验收

日期：2026-10-30（Australia/Perth）。基线 `6678bea`，开发分支 `dev/v15.7-step4-push`，备份分支 `backup/v15.7-before-step4-20261030`。

## 开发前执行规格

群体击退先锁定目标、位置、方向和非负整数位移量。每一离散拍先处理拍初占据格上的力传递与冲突，再将能够进入空格的单位同时移动1格；每次实际移动消耗1格剩余量。不能使用循环调用单体击退来模拟群体效果。

同向撞击时，撞击者停止，将全部尚未消耗位移量传给被撞者，与对方自身同向剩余量相加。拍初被占据的格子不因对方也准备移动而被当作空格；先处理传递，再移动。已消耗位移不再次传递。例如相邻A剩余2、B自身剩余1，A停止，B获得3。

以下是本次明确写出的**可调整原型执行选择**，不宣称旧策划已经最终确定：

1. 相邻单位互相迎面击退时，双方各抵消较小的剩余量；净余施加给被推动的一方。等量则双方停止。
2. 相隔一空格的单位同拍争用该格时，先抵消双方等量位移；等量均不进入，较大一方以净余继续移动。
3. 多个方向向同一被撞单位输入时，按有符号位移量同时求和；相反部分记为已抵消量，不能重复用于移动。同一拍内逐轮传播直到不存在被占据格上的待传递输入，再执行空格移动。
4. 同拍、同冲突类别、相同撞击者与被撞者的连续输入合为一个实际接触事件，输入量累加，避免链中已有位移与新传入位移重复计次。同拍不同参与者或不同类别的碰撞分别记录。
5. 同拍碰撞按碰撞坐标从左到右，坐标相同按撞击者编号、被撞者编号、冲突类别排序。普通传递坐标取被撞者拍初坐标；相邻迎面取两格中点；争用空格取该空格坐标。不同拍按发生顺序记录。
6. 越出边界的剩余位移立即消失，不产生怪物间碰撞或伤害。队伍所在格在此原型求解器中作为阻挡并清除剩余量，不擅自增加强制接触／穿越玩法；正常怪物前进的接触规则保持不变。

每拍位置整体提交后才记录本拍碰撞及移动事件；事件触发沿用步骤2的处理点，不在位移求解中插入遗物响应。碰撞默认无伤害，响应效果由具体监听配置决定。

维护并验证位移账本：初始位移总量 = 实际移动格数 + 反向抵消量 + 边界消失量 + 队伍阻挡消失量 + 剩余量。动作结束剩余量为0，不凭空产生位移。每拍及最终位置必须在界内、互不重叠且不与队伍格重叠。请求、敌人数组的排列不得影响结果或事件顺序。

此规格仅补齐同步击退的实现细节；不改变普通前进、不增加碰撞伤害、不引入质量或真实物理速度，也不设计正式新卡牌。原有单体击退、传递和边界结果必须继续通过冻结回归。

## 实现入口与记录

- `game/push.ts` 的planPushes为纯求解器，只读取编号、位置、战场、队伍格及显式请求；验证并计算完整逐拍计划后，resolvePushBatch才写入战斗状态。输入数组与请求均不被修改。
- 保留movement.ts中的pushEnemy单体入口，新增pushEnemies目标集合入口；二者统一委托同步求解器。重复集合ID先去重；原始批次的重复目标、非法量或重叠布局在写入前报错。零位移、无合法目标及战斗已终止时不创建新批次。
- 卡牌和监听支持pushAll全体击退、pushGroup显式多目标请求；单体／全体效果可选away、toward、left、right方向。away是旧单体规则的默认值，方向在该动作开始时锁定。显式请求可为不同目标指定不同量和方向，测试卡上的固定编号仅用于固定局面。
- 位移量使用非负安全整数，组内合计也须能精确表示；不会通过小数暗中增加格数。监听派生量沿用已有规则最终向上取整后交给求解器。没有任意求解步数截断，大量额外位移到边界后直接清除。
- 每拍整体替换敌人位置数组，随后先记录排序后的碰撞，再按移动前位置从左到右记录UNIT_MOVED。源头source与父事件沿用当前卡牌或监听上下文，原六类浮字事实及单体碰撞结构保持兼容。

COLLISION的push元数据包含batchId、tick、position及mode：transfer（向占据格传递）、opposed（相邻迎面）、converge（争用同一空格）。普通传递的value为本拍传入该接触的位移量；反向／争格的value为参与双方的剩余量之和，leftAmount、rightAmount、canceled另行记录。value不表示伤害，也不能直接当作本批实际移动格数。监听新增collisionMode条件，可区分三类碰撞。

当相反输入在静止中间单位合并时，左右输入各产生一次实际碰撞，抵消量由批次账本统一记录；不能把同一抵消量重复计到两个接触事件。`BattleState.pushHistory`保存每批初始输入、实际移动、抵消、边界／队伍阻挡消失量、剩余量、起止位置及拍数。事件查看器仅在debug=events时展示这些数据。

监听仍在整张卡直接效果完成、每只怪物行动完成等步骤2规定的处理点响应，不在求解循环中执行。碰撞监听可以造成伤害、治疗或追加新位移批次；其产生事件的父子关系、连锁权限、次数限制、最后击杀收尾和即时失败继续适用。响应导致失败时，已经完成的位移不回滚。

## 可操作开发局面

以下URL均在启动后的游戏地址使用；默认正常入口仍是原有三个布局、七张牌，不混入测试卡或测试遗物。

| URL参数 | 操作与预期 |
| --- | --- |
| `?scenario=pushTogether&debug=events` | 使用同步击退：#1保持8，#2从9到12；初始4，实际移动3，边界消失1 |
| `?scenario=pushSplit&debug=events` | 左右两敌同时向外2格，3／9变为1／11；移动4，无碰撞 |
| `?scenario=pushOpposed&debug=events` | 相隔一空格的左右力3与1冲突：5／7变为6／8；抵消2，实际移动2 |
| `?scenario=pushClash&debug=events` | 双方各2争格，保持5／7，抵消4，无移动，正常交还操作 |
| `?scenario=pushSandwich&debug=events` | #1和#3同时撞向#2，保持4／5／6；同位置两次碰撞按#1、#3排序，测试遗物各治疗1，队伍7变9 |
| `?scenario=pushChain&debug=events` | #1自身2和#2自身1相加后经#3传递；8／9／10变8／9／12，两个接触量为2和3，边界消失1 |
| `?scenario=pushLimits&debug=events` | 两侧敌人在0／12向外受阻，位移4全部消失，不制造怪物碰撞；重开清空账本 |
