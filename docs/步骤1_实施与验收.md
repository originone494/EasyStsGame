## 三层调用关系与数据职责

`content/*` 提供静态配置；`game/*` 创建和执行状态；`ui/*` 渲染并采集操作，`main.ts` 将操作交给 `act` 后重绘。界面交互会调用只读规则查询（如 `canMove`、`enemyOrder`），不自行结算伤害或修改牌堆。

新增 `game/model.ts` 作为共同类型入口，没有内容层或界面的运行时依赖。已有 `State`、`Card`、`Enemy` 和 `CardDef` 名称保留类型别名，避免破坏既有模块及测试入口。

| 模型 | 责任与约束 |
| --- | --- |
| `CardDefinition` | 卡牌名称、目标、效果、消耗标记等静态定义，由key索引 |
| `CardInstance` | 永久拥有的一张卡，含id、key、upgraded；同名复制品拥有不同id和独立布尔升级标记 |
| `BattleCardState` | 战斗对永久卡的引用，含相同id/key及可选临时状态；所在数组就是位置，避免维护两份牌区信息 |
| `BattleState.deck` | 永久牌组；出牌、洗牌和消耗不修改此数组 |
| `BattleState` | 单场战斗、队伍共享生命／坐标、敌人、牌区、事件事实记录和随机状态 |
| `CharacterDefinition`／`CharacterInstance` | 静态角色配置与队伍成员引用；成员没有独立生命／坐标 |
| `EnemyDefinition`／`EnemyState` | 敌人基础配置与本场编号、位置、生命、行动数值 |
| `EncounterDefinition`／`BattleConfig` | 三个布局及战场大小、生命、手牌数量、默认种子与临时角色 |
| `BattleEvent` | 集中定义现有六种事实日志；尚无触发器、队列顺序号或父事件协议，步骤2继续扩展 |

`createDeck` 分配实例ID并检查卡牌定义，`createBattleCards` 拒绝重复／非法ID并创建新的战斗对象。`createBattle(encounter, seed, ownedCards)` 可接收已有永久牌组，复制实例数据并建立新的牌区：ID与升级标记保留、战斗消耗恢复、临时状态清空，输入牌组不被共享修改。新卡分配可指定 `firstId`，未来整局管理器须使用不重复的递增ID。

升级标记只建立数据边界，本步骤不设计升级数值，不提供升级操作或升级版效果；删卡服务、正式永久牌组流程与存档也尚未接入。
