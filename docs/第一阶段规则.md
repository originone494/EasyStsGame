# 第一阶段规则与临时配置

## 交付与实现顺序

打开游戏直接战斗：横向格子、共享生命、敌人生命与移动距离、手牌和所有牌区数量；结束回合、重新开始、切换测试战斗；日志、胜败结算与立即重开。临时角色「行者」，无正式美术。

开发顺序：① 项目／状态／静态界面 → ② 抽牌／出牌／弃牌／洗牌／消耗 → ③ 攻击／连击／死亡／胜负 → ④ 移动／单体击退传递 → ⑤ 逐只怪物行动与接触 → ⑥ 三个布局／日志／重开 → ⑦ 规则检查与试玩。

## 执行规则

1. 回合开始补至 3 张，不弃掉超过 3 张的手牌。回合结束将剩余手牌弃置，随后执行怪物行动。
2. 普通牌免费，无出牌数量限制。
3. 抽牌不足时将弃牌堆洗入，继续抽牌；两个牌堆都空则停止。
4. 卡牌先从手牌进入独立执行区，完成全部效果后进入弃牌或消耗区；执行途中不能抽回自身。
5. 单体攻击可选任意存活敌人，无距离或阻挡限制。
6. 玩家移动终点越界或被占据，禁止执行，不消耗牌。玩家主动穿越敌人不触发接触（当前仅 1 格移动，无跨越情形）。
7. 怪物回合开始按与玩家距离由近到远，同距离按编号升序，整轮不重排。
8. 一只怪物完成全部行动后下一只才开始。
9. 怪物被其他怪物阻挡则停止，剩余移动作废。
10. 目标死亡后取消针对它的剩余攻击段；最后击杀后完成当前牌剩余效果和收尾再判胜。玩家生命归零立即失败，后续行动停止。
11. 怪物尝试迈入玩家所在格才接触，伤害后移除；相邻但未迈入不接触。
12. 单体击退逐格执行，碰到其他怪物时自身停止，将剩余量（含尚未迈出的该步）传给被撞者；碰撞无伤害；边界停止并丢弃剩余量；记录结构化碰撞事件。

执行区、空牌堆处理、接触检测、碰撞无伤害及传递方式均为公开的原型默认规则，后续可调整。补充原型默认：普通敌人全部因接触而移除且玩家存活，也判为本场胜利。配置中的敌人位置不得与队伍重叠。

开发局面使用 URL 参数进入：`?scenario=heal` 最后击杀后治疗；`?scenario=empty` 空牌堆与执行区；`?scenario=lethal` 接触致死；`?scenario=chain` 击退传递。种子与布局使用 `?seed=0&encounter=2` 指定。测试局面的牌数可能有意减少，不等同于正常七张牌开局。重开保持当前固定局面，切换战斗退出固定局面。

## 模块职责

`game/state.ts` 状态与初始化；`actions.ts` 校验和操作入口；`cards.ts` 效果与统一抽牌；`movement.ts` 玩家／怪物移动与击退；`turn.ts` 排序与回合；`resolution.ts` 伤害、死亡、结算；`random.ts` 固定种子洗牌；`scenarios.ts` 开发局面。

`content/cards.ts` 卡牌配置；`enemies.ts` 敌人配置；`encounters.ts` 布局及原型参数。`ui/` 仅渲染战场、手牌、状态与日志。界面不能直接改生命、位置或牌堆。

## 验收要求

- 三场战斗均可开始、结束、重开；非法操作不消耗卡牌、不破坏状态。
- 抽牌、洗牌、弃牌、消耗无丢失或复制。
- 怪物排序、阻挡、接触消失符合规则；击退传递不增加位移。
- 最后击杀收尾、玩家立即死亡正确。
- 相同配置、种子与操作序列复现同一结果。
