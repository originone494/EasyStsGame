# 步骤3：伤害执行规格与验收

日期：2026-10-30（Australia/Perth）。基线 `68e66d5`，开发分支 `dev/v15.7-step3-damage`，备份分支 `backup/v15.7-before-step3-20261030`。

## 开发前执行规格

统一采用 `D = max(0, ceil((B + ΣF) × ΠM))`。保留中间小数，只在每个独立伤害段／目标的最终结果取整。0伤害记录DAMAGE_RESOLVED但不记录HP_LOST；目标失效跳过，不伪造0伤害。过量伤害记录完整结算伤害，实际生命损失不超过目标原生命。直接生命损失不进入伤害公式。

群体伤害在开始时锁定合法目标、生命、位置及适用修正，逐目标独立计算，随后一次性写入全部生命并统一移除本批死亡目标；不能调用单体攻击循环模拟同步结算。全部状态写入后才记录事件及检查胜负，期间不派发监听。同批双方死亡先完成事实记录，再立即判玩家失败，取消后续动作及队列。

已确定的相对顺序：所有伤害事件先于所有死亡事件；同类敌方事件按距队伍由近到远、同距按固定编号排序；某次伤害先于其HP_LOST。

**本次公开的可调整实现选择：** 群体批次记录为全部DAMAGE_RESOLVED → 正数HP_LOST → ENEMY_DIED。各类沿用上述距离／编号排序，涉及队伍时队伍排在敌人前。三类事实共享批次编号，生命减少和死亡关联各自目标的伤害父事件。完整交叉顺序尚未由原文定案，此选择不宣称来自已确认策划；后续调整集中在批次事件记录函数和对应规格中，不改变同步状态写入。

每段群体伤害是独立批次。多段单体伤害不自动转移死亡目标；多段全体敌人效果在每段开始时重新锁定仍存活的敌人。执行直接卡牌效果完毕后才处理触发，沿用步骤2的FIFO、遗物快照和最后击杀收尾规则。

本步骤不设计护盾、免疫、正式遗物内容或天气数值。提供按伤害类别和目标筛选的修正数据入口，后续晴／雨／风适应仅对card类别接入，当前不提前启用天气。

## 实现与配置入口

- `game/damage.ts`：纯计算器calculateDamage、伤害来源分类、目标修正筛选、同步批次执行与独立批次事件记录函数。
- `game/resolution.ts`：保留damageEnemy／damagePlayer兼容入口，新增damageEnemies；统一委托批次执行，不再各自实现扣血公式。普通怪物接触明确标为contact。
- `game/model.ts`：DamageModifiers／DamageModifier／DamageRequest／DamageResult及伤害事件元数据。伤害类别为card（卡牌直接）、relic（遗物）、indirect（间接／临时触发）和contact（怪物接触）。来源source与伤害类别相互独立，卡牌引发的间接伤害可显式标为indirect。
- `game/cards.ts`、`eventQueue.ts`：单体、全体敌人及多段效果调用同一公式；遗物伤害不在进入公式前预先取整。临时监听仍按步骤2显式配置快照策略。

卡牌damage／damageAll效果可配置amount、flat固定修正数组、multipliers独立倍率数组，以及每段次数hits。damageAll为该动作开始时的全部存活敌人，无需选择单体目标；每段重新锁定目标。通用damageEnemies入口也支持指定敌人ID集合，并对重复ID去重。

`BattleState.damageModifiers`提供按kind和目标筛选的修正配置；未指定筛选时对所有伤害适用，实际生效的固定项与倍率在每次结算详情中记录。目标相关修正分别计算，不能复用首个目标的伤害结果。当前正常战斗的修正列表为空，因此原有数值与操作保持不变。

派生基础值通过baseTerms保存冻结／执行时读取的数值及系数，避免“已损生命3×0.1，再乘10”在中途变成0.30000000000000004。计算器将有限十进制数转为局部有理数，所有固定项、派生项和倍率计算结束后才执行唯一一次向上取整。`100×1.1=110`，同时仍保留略大于整数的真实尾数，不使用可能吞掉有效增量的epsilon修正。BigInt仅用于计算局部，不写入状态或事件，状态仍可JSON往返。

非有限配置、无法精确表示的整数结果、同一原始批次中的重复目标请求会在写入任何目标前报错。后者用于防止把多段误配置成同一同步批次；上层目标集合入口会先去重。没有合法目标或战斗已终止时不生成事件，也不消耗新的批次编号。

每条伤害事实包含batchId及damage详情：类别、基础项、派生项、固定修正、独立倍率、最终伤害、扣血前后生命、实际扣血。HP_LOST另含hpLossCause，区分damage和direct；监听可按伤害类别或生命减少原因筛选。纯粹失去生命不消耗伤害批次，不受伤害倍率修正。

## 可操作测试局面

启动后通过以下URL参数进入；添加debug=events可展开查看公式、类别、批次及事件日志。测试卡与测试倍率不加入正常牌组或正式内容。

| URL参数 | 操作与预期 |
| --- | --- |
| `?scenario=damageFormula&debug=events` | 对唯一敌人打出倍率攻击：10×1.2×1.3取整16，敌人14/30 |
| `?scenario=damageMulti&debug=events` | 对唯一敌人打出分段取整：3段分别结算2，共6伤害，敌人24/30；三段各有批次 |
| `?scenario=damageWave&debug=events` | 使用同步横扫：同时击杀左右敌人，先直接治疗2，再分别触发两次死亡治疗3，队伍15/20胜利 |
| `?scenario=damagePartial&debug=events` | 使用同步横扫：两只死亡，剩余重甲兽6/10；队伍15/20，战斗继续 |
| `?scenario=damageKinds&debug=events` | 使用基础攻击：测试card倍率使直接伤害为8，遗物和临时触发各为4；敌人最终14/30 |
